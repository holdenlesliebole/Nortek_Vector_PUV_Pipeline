\begin{abstract}
\noindent
This guide is for anyone running the Nortek Vector PUV pipeline on their own data or using
the San Diego catalog it produced. The pipeline takes raw pressure--velocity (PUV) instrument
files through four built levels into quality-controlled time series, hourly wave spectra,
wave-forcing metrics and infragravity diagnostics, driven by one config file per deployment.
Sections~\ref{sec:start}--\ref{sec:running} cover installing, configuring and running a
deployment. Section~\ref{sec:qc} covers the per-channel quality control and the flags every
segment carries, and Section~\ref{sec:prov} the provenance stamps and the published catalog.
Sections~\ref{sec:methods}--\ref{sec:outputs} are the methods and output reference. To run the
code, read Sections~\ref{sec:start}--\ref{sec:prov}. The repository \code{README.md} is kept
current with every code change and is the place to check if this guide and the code ever
disagree; \code{CHANGELOG.md} lists the changes.
\end{abstract}

\section{What the pipeline is}
\label{sec:intro}

Bottom-mounted Nortek Vector acoustic Doppler velocimeters (ADVs) record pressure and
three-component velocity continuously at 2~Hz. The pipeline reads either form of Nortek raw
data, the ExploreV ASCII export (\code{.dat}/\code{.sen}/\code{.hdr}) or the recorder binary
(\code{.VEC}/\code{.vec}/\code{.049}), which it decodes itself (\S\ref{sec:vec}), so neither
ExploreV nor Windows is needed. Every deployment runs through the same drivers and produces
the same output structures. The San Diego catalog built with it holds 65 instrument-records
from 46 deployments, 2014--2026, at Torrey Pines, Los Pe\~nasquitos, Solana Beach, Cardiff,
SIO Pier, Imperial Beach, Coronado and Catalina Island, at nominal depths of 5 to 30~m. It is
published on the SIO group share as catalog version 2026-10-14.1.

\begin{center}
\begin{tabular}{@{}c l p{9.3cm}@{}}
\toprule
Level & Output & What it contains \\
\midrule
\textbf{L1} & QC'd 2~Hz time series & Per-file bursts, clock drift and offset, tilt correction,
  per-channel quality control, sound-speed correction, rotation to a geographic frame \\
\textbf{L2} & Hourly segments & Multitaper spectra, pressure correction to surface elevation,
  bulk wave parameters ($H_s$, $T_p$, direction), near-bed velocity, bed and Reynolds stress,
  velocity moments, pressure--velocity consistency diagnostics \\
\textbf{L3} & Forcing metrics & Band energy (infragravity, swell, sea), storm events,
  transport proxies (Shields, settling velocity, Rouse, mobilization), tidal and subtidal
  currents \\
\textbf{L4} & Nonlinear / IG diagnostics & Surface elevation in three bands,
  incident/reflected infragravity split, bound/free infragravity separation, bispectra,
  frequency-resolved moments, velocity PDFs; \code{L4\_xspec} holds pairwise infragravity
  cross-spectra for multi-instrument deployments \\
\textbf{L5} & \emph{(planned)} & PUV--altimeter merge: bed change against forcing \\
\bottomrule
\end{tabular}
\end{center}

\noindent
L1--L4 need no altimeter data. Each level reads the previous level's \code{.mat} files, so the
levels run in order L1$\rightarrow$L2$\rightarrow$L3$\rightarrow$L4.

\section{Getting started}
\label{sec:start}

\subsection{Requirements}

\begin{itemize}
\item \textbf{MATLAB R2025a}, the release used for development and testing; earlier releases
  are untested. Required toolboxes: \textbf{Signal Processing} (DPSS multitaper spectra,
  \code{cpsd}) and \textbf{Aerospace} (\code{igrfmagm}, the IGRF magnetic declination applied
  at L1). The \textbf{Parallel Computing Toolbox} is optional; it speeds up
  \code{PUV\_L4\_bispectra}, and the serial path gives bit-identical results. The Mapping and
  Statistics toolboxes are not needed by L1--L4.
\item \textbf{Files outside the repository, for L3 only.} L1, L2 and L4 use only files in the
  repository. L3 needs 11 outside files, listed with their SHA-256 in
  \code{shared/external\_deps.m}: \code{t\_tide} version~1.3 (Pawlowicz, Beardsley and Lentz,
  2002; eight files, not redistributed because its license is informal) for the tidal fit, and
  the SIO Coastal Processes lab toolbox function \code{read\_MOPline2.m} with its helpers
  \code{get\_k.m} and \code{xyRotate.m} for the CDIP MOP storm reference. Without
  \code{t\_tide}, L3 stops with an error unless \code{opts.allowNoTides = true} is passed;
  without the lab toolbox, L3 runs without the MOP storm reference and records the fallback.
  \code{README.md}, ``External dependencies'', gives the fallback folders the code searches.
\item \textbf{Network access} at runtime for: the CDIP shore-normal angle when a config uses
  \code{instr.mopStation}; the CDIP offshore reference (\code{instr.refStation}); and NOAA tide
  predictions at L3 (\S\ref{sec:l3methods}). A failed NOAA download is an error unless
  \code{opts.allowTtideFallback = true}.
\item \textbf{Raw data}: point \code{cfg.rawDataRoot} at any folder. The bundled San Diego
  configs read \code{/Volumes/group/PUV\_data/Vector/}, with deployment metadata in
  \code{/Volumes/group/DeploymentNotes/}.
\end{itemize}

\subsection{First run}

\begin{lstlisting}
% 1. From the repo root, put the pipeline on the MATLAB path
%    (startup_puv leaves outputs/, raw_cache/, .git/ and .claude/ off it):
cd /path/to/PUV_Pipeline
startup_puv

% 2. Optional: cache the raw files locally. Network reads are slow, and the
%    L1 driver reads raw_cache/<deployment>/ when it exists.
reg = deployment_registry();
f = reg('TBR23');
cfg = f();
copy_raw_to_local(cfg);

% 3. Run the levels in order. Each driver has deployment_name = '...' at the top.
PUV_L1_driver        % raw -> QC'd time series   (outputs/L1/TBR23/)
PUV_L2_driver        % spectra + bulk params     (outputs/L2/TBR23/)
PUV_L3_driver        % forcing characterization  (outputs/L3/TBR23/)
PUV_L4_driver        % nonlinear / IG dynamics   (outputs/L4/TBR23/)
PUV_L4_xspec_driver  % pairwise IG cross-spectra (two or more instruments)
\end{lstlisting}

\noindent
The batch scripts \code{PUV\_L1\_run\_all} \dots\ \code{PUV\_L4\_run\_all} and
\code{PUV\_L4\_xspec\_run\_all} process every registered deployment and skip records whose
output already exists. \code{PUV\_L4\_run\_all} leaves out \code{bispectra}, the slow module,
by default (\code{runBispectra = false}) and says so at the end. Output files, each with a \code{.prov.json} sidecar (\S\ref{sec:prov}):
\begin{itemize}
\item \code{outputs/L1/<deployment>/<label>\_processed.mat}
\item \code{outputs/L\{2,3,4\}/<deployment>/<label>\_L\{2,3,4\}.mat}
\item \code{outputs/L4\_xspec/<deployment>/xspec.mat}
\end{itemize} Outputs are not version-controlled; they are reproducible from raw data
plus code.

To check an installation, run the self-contained tests:
\begin{lstlisting}
run_all_tests                         % 23 tests: PASS / FAIL / SKIP and a total
run_all_tests('includeData', true)    % also tests that read outputs/, the server or the network
\end{lstlisting}
From a shell use plain \code{matlab -batch "startup\_puv; run\_all\_tests"}: on R2025a under
macOS, adding \code{-nodisplay} makes \code{matlab -batch} exit 0 even when the command errors.

\section{Configuring a deployment}
\label{sec:config}

\code{config/deployment\_registry.m} maps a short name to a config function, for example
\code{'TBR23'} $\rightarrow$ \code{@TBR23\_config}; 50 names are registered. Names follow
\code{SITE + year + optional season letter} (\code{TOR24S} = Torrey spring 2024;
\code{SIO24A}--\code{C} = SIO Pier 2024 in order). \code{TBR23} (Torrey Pines Beach Recovery
2023) is the one legacy exception, and \code{TOR23S} is registered as an alias of it. For the
pre-2019 seasons, which ran one instrument at a fixed station and swapped it every 5--6 weeks,
the trailing letter is the deployment's ordinal within that winter (\code{TOR15A} = first Torrey
deployment of 2015--16).

\subsection{Adding a new deployment}

The full walkthrough is \code{docs/NEW\_DEPLOYMENT.md}. In outline:
\begin{enumerate}
\item Copy \code{config/TEMPLATE\_config.m} to \code{config/<NAME>\_config.m} and rename the
  function.
\item Per instrument set \code{label}, \code{filePrefix}, \code{rawSubfolder}, \code{latlon},
  \code{depth\_nominal}, \code{doffp} (pressure-port height above the bed, m; required),
  \code{heading} and a shore-normal source. San Diego values come from
  \code{/Volumes/group/DeploymentNotes/*.xls}; \code{config/DOFFP\_LOOKUP\_CHECKLIST.md} lists
  where to look and the traps (rows labeled only ``Redeploy'', \code{doffp} quoted to the
  altimeter face).
\item Put the \textbf{source of every \code{doffp}, \code{latlon}, \code{heading} and
  \code{shorenormal} on the same line} as a comment: workbook, sheet, row, serial number and the
  cell's wording. \code{validation/audit\_config\_provenance.m} lists values without one. A
  surveyed GPS fix carries 5--7 decimal places; a coordinate at 3 decimal places
  (about 111~m) was placed by hand.
\item Set \code{cfg.qcOpts.Tvalid} to the site's water-temperature range (\S\ref{sec:qcopts})
  and \code{cfg.tideStation} to the nearest NOAA CO-OPS harmonic station
  (\S\ref{sec:l3methods}).
\item An instrument that failed in the field stays in the config with
  \code{instruments(k).knownFailed = '<cause>; <source>'}, so the drivers skip it
  (\S\ref{sec:running}).
\item Register the deployment, then run \code{validation/audit\_registry\_loads.m}. It is the
  one check that does not swallow a config that throws an error, and it lists configured
  instruments with no L1 as known failures or missing.
\end{enumerate}

\paragraph{Heading.} Leave \code{heading = NaN} to use the median of the onboard compass,
unless the compass drifts or steps while the tilt stays constant; then use the mount heading
from the field log. A record whose logged and compass headings differ by more than
10\degree\ and that keeps the compass value goes in
\code{shared/heading\_disputed\_records.m} (12 records at present).

\paragraph{Shore-normal.} \code{instr.shorenormal = <deg>} (offshore-pointing bearing, any site;
takes precedence) or \code{instr.mopStation = 'D0580'} (fetched from CDIP, California). With
neither, velocity stays in buoy coordinates and the L4 incident/reflected split is skipped.

\paragraph{Pre-2019 recorders.} For a deployment ingested from raw binary (\S\ref{sec:vec}) set
\code{instr.rawFormat = 'VEC'}. For a firmware-1.21 recorder with a wrong clock epoch add
\code{instr.clockSource = 'filename'}, \code{instr.deployYear}, \code{instr.clockOffsetHours}
(\S\ref{sec:vec}) and \code{cfg.qcOpts.cutoffGapSec = 60}. \code{config/TorreyOffshore\_config.m}
is a worked example.

\subsection{Quality-control options: \texttt{cfg.qcOpts}}
\label{sec:qcopts}

L1 quality control reads one option struct. The defaults live in
\code{L1\_raw\_to\_qc/l1\_qc\_opts.m}, overlaid field by field with \code{cfg.qcOpts}; the
result is stored in each L1 file at \code{PUV.qc.opts}, and
\code{validation/audit\_L1\_qcopts.m} compares the stored options with the configs.

\begin{center}
\begin{tabular}{@{}l l p{7.7cm}@{}}
\toprule
Field & Default & Meaning \\
\midrule
\code{corrMin}    & 70 & Minimum beam correlation (\%), Nortek's recommendation. \\
\code{Tvalid}     & \code{[-2 40]} & \textbf{Plausible water-temperature range (\degree C).}
  The primary thermistor-failure test. See the boxed note. \\
\code{maxJump}    & \code{Inf} & Optional per-sample temperature-step gate; \code{Inf} = off. \\
\code{tiltStdMax} & 2  & Moving-window standard deviation of pitch or roll above which the
  tilt counts as unstable (\degree). \\
\code{tiltAbsMax} & 30 & Absolute tilt = toppled frame; always invalidates velocity (\degree). \\
\code{tiltWindow} & 120 & Samples in the moving window (60~s at 2~Hz). \\
\code{cFactorTol} & 0.002 & Below this fractional sound-speed difference no rescale is
  applied. \\
\code{cutoffGapSec} & 1 & Gap between consecutive sensor records that counts as a battery
  cutoff (s). 60 for the firmware-1.21 recorders, which leave a benign few-second gap in
  nearly every hourly file. Read by \code{PUV\_raw\_process}. \\
\code{offBedDbar} & absent (off) & Vertical-transit pressure test (dbar). Off in every
  config; it stays off until the next deliberate L1 rebuild. \\
\bottomrule
\end{tabular}
\end{center}

\boxnote{\textbf{Set \code{Tvalid} to the site's water-temperature range.} The default
\code{[-2 40]} catches gross failures (freezing, firmware garbage) anywhere, but it accepts an
implausibly cold reading from a failing thermistor. Every San Diego and Catalina config sets
\code{cfg.qcOpts.Tvalid = [9 26]}; a December reading of 8\,\degree C at Torrey Pines is not
real water. L1 uses it for the thermistor test and L3 for the per-segment viscosity.
Section~\ref{sec:tvalid} explains why a range test is safe for good data.}

\section{Raw-binary ingestion and the pre-2019 archive}
\label{sec:vec}

Most deployments before 2019 exist only as recorder binary (\code{.VEC}/\code{.vec}/\code{.049})
with no ExploreV export, and where an export exists it can be partial: \code{TORREY02\_1.dat}
covers 5.1~days of a 174-day record and ends mid-line. The pipeline therefore decodes the binary
with \code{L1\_raw\_to\_qc/read\_VEC.m}. The decoder matches the one ASCII export that overlaps
it: over 886{,}319 velocity and 443{,}131 system records, every integer-valued column (velocity
counts, amplitude, correlation, clock, flags) is identical, and pressure and attitude agree to
the ASCII's print precision (\code{test\_read\_VEC.m}).

\subsection{Choosing the ingest path}

Set \code{instr.rawFormat} to \code{'VEC'} or \code{'ASCII'} to force a path. Left unset, L1
prefers the ASCII export when a \code{.dat} exists, which is wrong when an export was
interrupted, so L1 warns whenever both forms are present. Sampling rate and coordinate system
come from the binary's User Configuration record, so a deployment with a 0-byte \code{.hdr}
still ingests.

\subsection{Two things the firmware-1.21 recorders get wrong}

\paragraph{Sample rate.} The configuration field implies 8~Hz on this firmware, but the records
are 2~Hz. \code{read\_VEC} measures the rate from the ratio of velocity to 1~Hz system records
and warns when it disagrees with the configuration. Three checks agree: the decoded record
ratio is 2, the system-record count equals the clock span in seconds, and the field checkout
sheet states ``Sample rate = 2Hz, Samples per block = 7168, Block time = 3600~s''.
\code{instr.decimateTo} handles a genuine 8~Hz record.

\paragraph{Clock epoch and time zone.} These recorders stamp their first sample with a wrong
epoch (2000-01-01 or 2002-01-01). The clock runs correctly from that wrong start, and the
recorder names each hourly file \code{MMDDHHMM} for the hour it was set to. With
\code{instr.clockSource = 'filename'} and \code{instr.deployYear},
\code{vec\_clock\_from\_filenames.m} recovers one constant offset, the median over every file,
and rejects it (on the 98th percentile) unless it is nearly constant, so a wrong filename
convention fails loudly. Against the one instrument whose clock was set correctly, the
filename-derived time agrees to 33~s.

The recovered clock is \textbf{Pacific local time, not UTC}. Cross-correlating L2 depth with
the NOAA tide prediction placed every filename-clocked record at a lag of $-7$ or $-8$~h, so
\code{instr.clockOffsetHours} is added at L1: 7~h for the 2014 records, 8~h for the later ones.
It is a fixed offset, not a time-zone conversion; records entirely in daylight time still want
8~h. Derive the sign rather than fitting it: if the data are $D(t) = W(t+\delta)$ and the
prediction is $P(t) = W(t)$, the best lag is $L = -\delta$, so a lag of $-8$~h means the labels
are slow and 8~h is \emph{added}. Applying $-8$ doubles the error and still looks like a match
in a lag scan. \code{scripts/audit\_clock\_lag.m} checks every filename-clocked record at lag~0.

\subsection{Robustness the archive forced}

\begin{itemize}
\item \textbf{Benign hourly gaps.} Firmware 1.21 drops a few seconds in nearly every hourly file;
  \code{cutoffGapSec = 60} keeps them from being read as battery death.
\item \textbf{Power-on glitch.} Some recorders write one sample at power-on, then a long gap,
  then the deployment (TOR16B: one ping, then 2463~s). The leading sample is trimmed rather than
  ending the record.
\item \textbf{Battery-death clock drift.} A dying battery pulls the clock off in the last hours;
  the record is truncated at that jump.
\item \textbf{Year-crossing deployments.} \code{MMDDHHMM} names sort January ahead of the
  previous November, so files are ordered by their clock, not by name.
\end{itemize}

\subsection{Split recorder files}

The recorder splits large records at 100~MiB with a \code{\_N} suffix. Each raw file is treated
as its own burst and the battery-cutoff test runs within each burst, so a seam between files
is never read as a gap. Concatenating the files first would let one lost second at a seam
truncate months of good data.

\section{Running the pipeline, level by level}
\label{sec:running}

Each level has a driver (\code{PUV\_L\{n\}\_driver.m}) with a \code{deployment\_name} variable at
the top, and a batch version (\code{PUV\_L\{n\}\_run\_all.m}) that loops over the registry.

\begin{description}
\item[L1: raw to QC'd time series.] Reads the raw files (ASCII or binary), corrects clock drift
  and offset, applies per-channel QC (\S\ref{sec:qc}), corrects tilt and sound speed, and
  rotates velocity to the buoy frame ($+x$ west, $+y$ north, $+z$ up). Writes
  \code{<label>\_processed.mat} holding a \code{PUV} struct and its \code{PUV.qc} sub-struct.
\item[L2: spectra and wave statistics.] Cuts the L1 series into 1-hour segments, estimates
  multitaper spectra, converts pressure to surface elevation, and computes bulk wave parameters,
  near-bed velocity, bed and Reynolds stress and velocity moments. Most analyses read this level.
\item[L3: forcing characterization.] Band energy, storm events (with a CDIP MOP reference for
  PUV gaps), transport proxies, and tidal and subtidal currents.
\item[L4: nonlinear and IG dynamics.] Band-passed surface elevation, the incident/reflected and
  bound/free infragravity splits, bispectra, frequency-resolved moments and velocity PDFs.
  \code{PUV\_L4\_xspec\_driver} adds pairwise infragravity cross-spectra for deployments with two
  or more instruments; it is the only product that reads \code{LATLON}, and it must be rebuilt
  whenever any member L4 changes.
\end{description}

\paragraph{Failures.} Every driver keeps going when one record fails, then ends with an error
naming each config that threw and each record it did not write, so \code{matlab -batch} exits
nonzero. Seven of the 72 configured records have no L1 because the instrument failed in the
field (SIO24B, SIO24C, SIO25A, SOL23/MOP651\_5m, TOR24S/MOP586\_15m, TOR24W/MOP586\_5m,
TOR25S/MOP586\_5m). Their configs carry \code{knownFailed = '<cause>; <source>'}, and the drivers
skip them with a \code{KNOWN FAILED} line, so an error at the end means a new failure.

\paragraph{Rebuild order.} L3 and L4 are built against L2 as it stood at build time. After any
L1 or L2 rerun, rebuild L3 and L4 (and \code{L4\_xspec}), and never index an L4 per-segment
array with an L2 segment index: match on time with \code{shared/l4\_l2\_index\_map.m}. Equal
segment counts do not prove alignment, and MATLAB silently accepts a logical mask shorter than
the array it indexes. A script that recomputes part of an L4 must save the complete struct.

\paragraph{Audits.} After changing configs or rebuilding, run
\code{validation/audit\_registry\_loads.m} (every config builds),
\code{validation/audit\_L1\_qcopts.m} (stored L1 options match the configs),
\code{validation/audit\_L4\_coverage.m} (every L4 complete, aligned to its L2 and consistent
with it), \code{validation/audit\_config\_provenance.m} (geometry values without a source) and
\code{scripts/audit\_clock\_lag.m} (filename-clocked records at lag~0). These read \code{outputs/}.

\section{Quality control and segment flags}
\label{sec:qc}

The guiding principle is \textbf{channel decoupling}: pressure, velocity, temperature and tilt
are judged independently, and one dead channel never discards data from a channel that is
still good.

\subsection{Why channel decoupling}

A Nortek Vector has a Doppler velocity sensor and an auxiliary sensor block (pressure,
thermistor, compass, tilt), and the two fail independently. The original QC nulled an entire
data row whenever any channel failed. At Torrey Pines in December 2023 (TOR23W/MOP586\_10m), one
frame's pressure sensor and thermistor died during a storm while its Doppler channel stayed
healthy (beam correlations 92--97\%); the old QC discarded the velocity anyway, and 120~hours
of storm-peak velocity were recovered by the per-channel rework of July 2026
(\code{docs/L1\_sensor\_block\_failure\_2026-07-09.md}).

\subsection{Per-channel validity}

\code{L1\_raw\_to\_qc/puv\_channel\_qc.m} computes per-sample masks:
\begin{itemize}
\item \textbf{Velocity} is valid when the minimum beam correlation is at least \code{corrMin},
  the frame is not toppled, and the tilt is stable (below). A dead pressure sensor or
  thermistor does not invalidate velocity.
\item \textbf{Pressure} is valid inside $[p_\text{ref}/2,\, 2p_\text{ref}]$, where $p_\text{ref}$
  is the median of the in-water samples (above 0.5~dbar) in the first 10\% of the record, at
  least 1000 samples. A reference taken early survives a sensor that saturates later, which a
  whole-record median does not.
\item \textbf{Temperature} is valid inside \code{Tvalid}, optionally with the step gate
  \code{maxJump}.
\item \textbf{Tilt} is judged two ways: a moving standard deviation above \code{tiltStdMax} is
  an unstable reading; an absolute tilt beyond \code{tiltAbsMax} means the frame toppled or moved.
\end{itemize}

\noindent
Tilt describes the measurement geometry, so it is not treated like the other auxiliary
channels. An absolute tilt beyond 30\degree\ always invalidates velocity, whatever the state of
any other channel. A variability spike invalidates velocity only when the sensor block is
trusted; when the block has failed, its jittery tilt reading is discarded and a static tilt from
the healthy part of the record is used for the rotation instead.

\subsection{The temperature test}
\label{sec:tvalid}

The instrument computes sound speed from its measured temperature and uses it to scale
velocity, so a failed thermistor biases velocity. The test for ``failed'' is physical
plausibility (\code{Tvalid}), not distance from the record median. A distance test would flag a
genuine cold-upwelling event and corrupt its velocity through the rescale; a range test does
not, because a real seawater temperature is valid whatever the rest of the record did.

\subsection{Sound-speed correction}

Where the instrument's sound speed differs from the one implied by a valid temperature by more
than \code{cFactorTol}, velocity is rescaled following the Nortek manual (N3015-030,
\S2.4.9):
\[
  V_\text{corrected} = V_\text{recorded}\,\frac{c_\text{true}}{c_\text{measured}} .
\]
The reference sound speed comes from a companion frame if the config supplies one
(\code{cfg.soundSpeedRef}), otherwise from the instrument's own healthy temperature--sound-speed
relation at a reference temperature taken from in-water, plausible samples, never extrapolated.
On healthy data the factor is exactly~1.

\subsection{Segment flags}

Nothing reconstructed or rescaled is presented as a clean measurement. Every L2 segment carries:

\begin{center}
\begin{tabular}{@{}l p{10.5cm}@{}}
\toprule
Field & Meaning \\
\midrule
\code{segValid}      & All channels good (the original meaning). \\
\code{segValid\_vel} & Velocity products (moments, mean flow, Reynolds stress) usable. \\
\code{segValid\_p}   & Pressure products ($H_s$, $S_\eta$, depth) usable. \\
\code{qc\_flag}      & 1~good, 2~not evaluated, 3~suspect (recovered or sound-speed rescaled),
  4~fail (physically implausible). Anything reconstructed is~3, never~1. \\
\code{Hs\_source}    & \code{'measured'}, \code{'reconstructed'} or \code{'none'}. \\
\code{vel\_c\_factor} & The sound-speed factor (exactly~1 on healthy data). \\
\code{vel\_c\_corrected} & Whether the sound-speed rescale was applied. \\
\code{qc\_record}    & Record-level Z flag (pressure against velocity-predicted pressure):
  \code{ok}, \code{FLAG} or \code{insufficient}. It marks a record and drops nothing. \\
\bottomrule
\end{tabular}
\end{center}

\noindent
For clean-only forcing, filter on \qcflag{1}. To use storm-peak velocity recovered from a
sensor-block failure, take \qcflag{3} with \code{segValid\_vel} true and carry the few-percent
scale uncertainty of the rescale. A segment whose pressure is present but implausible ($H_s/h$
above 1.5, or depth more than 50\% from nominal) is \qcflag{4}.

Two lists apply at reporting time and drop nothing from the files:
\code{shared/excluded\_records.m} (RUBY22/MOP582\_30m, whose pressure sensor was deployed below
its rated depth; RUBY22/MOP579\_6m) and \code{shared/heading\_disputed\_records.m}, whose
directional quantities are uncertain by at least 10\degree.

\subsection{Failure signatures}
\label{sec:signatures}

Three failure modes appear in the archive. A scan of the \code{.sen} files, which carry battery,
sound speed, heading and tilt, separates the first two without reading the much larger
\code{.dat}:

\begin{center}
\begin{tabular}{@{}l p{7.5cm} c@{}}
\toprule
Signature & How to recognize it & Velocity recoverable? \\
\midrule
Sensor-block failure & Temperature implausible, sound speed steps, battery erratic; tilt stays
  small & Yes (with the rescale) \\
Toppled or moved frame & Temperature, sound speed, battery normal; tilt passes 30\degree\ or
  drifts steadily & No \\
Doppler failure & Beam correlation collapses to about 5--10\%, amplitude drops; the auxiliary
  block looks fine & No \\
\bottomrule
\end{tabular}
\end{center}

\noindent
Beam correlation lives in the \code{.dat}, so the \code{.sen} scan cannot see a Doppler failure.

\section{Provenance and the published catalog}
\label{sec:prov}

\paragraph{Sidecars.} Every output written by the drivers or the catalog rebuild carries a
provenance block, embedded as a \code{prov} field and written beside the file as
\code{<file>.prov.json} (\code{shared/save\_with\_provenance.m}, \code{build\_provenance.m}). It
records a \code{build\_id}, the git commit and whether the tree was dirty (\code{'unknown (no
git)'} in a checkout without \code{.git}), where each key function resolved, the parents'
\code{build\_id}s, the external files with their SHA-256, the physical choices applied (for L3:
$D_{50}$ and its source, settling-velocity constants, viscosity model, \code{Tvalid}, tide
station and tidal source), any fallback taken, and the SHA-256 of the saved bytes. The drivers
have stamped since 2026-10-15. In catalog 2026-10-14.1 the 65 L2, 65 L3, 65 L4 and 9
\code{L4\_xspec} sidecars were written at build time and the 65 L1 sidecars were backfilled
(their \code{backfilled} field says so).

\paragraph{Server catalog.} \code{/Volumes/group/PUV\_data/Vector/Processed\_HLB/}, laid out
\code{<DEPLOYMENT>/Level\{1,2,3,4\}\_QC/<label>\_*.mat} plus \code{L4\_xspec}, each file with its
sidecar. Beside them: \code{manifest.csv} (size, \code{sha256}, \code{build\_id},
\code{git\_hash}, \code{backfilled}, \code{catalog\_version\_first} per file), every previous
manifest, a server \code{CHANGELOG.md} per catalog version, and a generated \code{README.md}.
Catalog versions are \code{YYYY-MM-DD.N}. To tell which version a copy belongs to, look up its
SHA-256 in the manifest.

\paragraph{Publishing.} \code{scripts/copy\_to\_server.m} checks every file with
\code{shared/check\_prov.m} before copying. It refuses outright a file with no provenance, bytes
that differ from the sidecar, a config or derived value that no longer matches (including the
tide station), or a parent rebuilt since. It refuses, until a change entry in
\code{docs/catalog\_changes/} acknowledges it, a file whose level's code changed since the build,
an external dependency that changed, a recorded fallback, or uncommitted code. An entry can be
acknowledgement-only (\code{changes: false}) when the code changed but no output value did. Rule
and format: \code{docs/catalog\_changes/README.md}.

\paragraph{No writes into \code{outputs/} from elsewhere.} Only this pipeline writes
\code{outputs/}. An edit from another repository, a notebook or by hand makes a file's bytes
disagree with its sidecar, and the push refuses it. To change an output, change the code or
config here and rebuild.

\section{Methods}
\label{sec:methods}

A longer methods text, with the history of each change, is in \code{docs/compile\_sections.pdf}.

\subsection{L1: quality control and coordinate rotation}

Each raw file is read as one burst (ASCII or binary, \S\ref{sec:vec}). Clock drift measured at
recovery is removed linearly over the deployment, and \code{clockOffsetHours} is added for
filename-clocked records. A gap between sensor records longer than \code{cutoffGapSec} marks
battery depletion and everything after the first such gap is discarded; a power-on glitch at the
start is trimmed instead. Per-channel QC (\S\ref{sec:qc}) and the sound-speed correction follow.

Where the median tilt exceeds 1\degree, velocity is rotated to the local vertical sample by sample
with the measured pitch $\phi$ and roll $\theta$. The code applies roll first, then pitch:
\[
  \mathbf{v}_\text{corrected}
  = \mathbf{R}_\text{pitch}(\phi)\,\mathbf{R}_\text{roll}(\theta)\,\mathbf{v}_\text{raw},
\]
with $\mathbf{R}_\text{roll}$ a rotation about $x$ and $\mathbf{R}_\text{pitch}$ about $y$.
Revisions of this guide before October 2026 wrote the product in the other order; the
components in \code{PUV\_raw\_process.m} are those of the order above. Whether that order matches
Nortek's pitch and roll convention has not been checked.

Velocity is then rotated to the buoy frame ($+x$ west, $+y$ north, $+z$ up; left-handed, the
CDIP MOP convention). XYZ records use the heading (the compass median, or the logged mount heading
where the compass drifts; \S\ref{sec:config}) plus the IGRF magnetic declination at the deployment
position and start date (\code{igrfmagm}, IGRF-14 where available, else IGRF-13 capped at 2025.0).
Records stored in Nortek ENU coordinates, which are magnetic, have the same declination added
(\code{enu\_to\_buoy\_frame.m}, since 2026-10-07; about 11.07\degree\ at San Diego).
\code{PUV.rotation.coordSystem} and \code{.declinationApplied} record which path ran.

\subsection{L2: spectral analysis}

\paragraph{Segmentation.} The L1 series is cut into non-overlapping 1-hour segments of 7200
samples starting at the first UTC top of the hour, the cadence of the CDIP MOP hindcast. Random
Doppler error in a segment mean falls as $1/\sqrt{N}$, so the 7200-sample mean has a noise floor
$\sqrt{7200/2048} \approx 1.9$ times lower than the 2048-sample (17-minute) segments used before
May 2026. Velocity and pressure products are kept separately when no more than 10\% of that
channel is NaN. Remaining gaps are interpolated linearly in the interior and held at the nearest
valid value at a segment edge (since 2026-10-09; before, edge gaps were extrapolated, which
inflated infragravity and velocity statistics). Velocity is rotated to shore-normal ($+x$
onshore, $+y$ alongshore north) with \code{instr.shorenormal} or the CDIP angle for
\code{instr.mopStation}. Depth is $H = \overline{P}\times 10^4/(\rho g) + z_s$ with
$\rho = 1025$~kg\,m$^{-3}$, $g = 9.81$~m\,s$^{-2}$, $\overline{P}$ in dbar, and $z_s$ the
pressure-port height above the bed (\code{doffp}).

\paragraph{Spectral estimation.} Spectra use the multitaper method of Thomson (1982) on the
whole segment with $NW = 4$ (\code{shared/psd\_multitaper.m}). The code keeps the Slepian
tapers whose concentration eigenvalue exceeds 0.99, which for $NW = 4$ is $K = 6$ (the seventh
has eigenvalue 0.937), so each bin has about 12 degrees of freedom. Bins are spaced
$\Delta f = 2.78\times10^{-4}$~Hz and the resolution bandwidth is
$2NW/T = 2.2\times10^{-3}$~Hz. Auto- and cross-spectra use the same tapers, which keeps the
directional moments consistent. Earlier revisions of this guide said $K = 7$; the code has kept
six since it was written. Welch (\code{opts.spectralMethod = 'welch'}) remains available; the
comparison that chose multitaper is \code{docs/multitaper\_writeup.pdf}.

\paragraph{Pressure correction.} $K_p(f) = \cosh(kz_s)/\cosh(kH)$, with $k(f)$ from
$\omega^2 = gk\tanh(kH)$ by Newton iteration, and $S_\eta = S_p / K_p^2$. Bins with
$K_p < 0.1$ are set to zero; the cutoff $f_\text{cut}$ is stored.

\paragraph{Bulk parameters.} $H_s = 4\sqrt{m_0}$, $m_0 = \int S_\eta\,df$, over the total
(0.004--0.25~Hz), sea--swell (0.04--0.25~Hz) and infragravity (0.004--0.04~Hz) bands. $T_p$ is
the period of the sea--swell spectral maximum. $T_{m02} = \sqrt{m_0/m_2}$ and the energy flux
$F = \rho g \int c_g S_\eta\,df$ use the total band. The mean direction is
$\operatorname{atan2}(\bar b_1, \bar a_1)$ from the first-harmonic moments of the
pressure--velocity cross-spectra, weighted by $S_\eta$ over the sea--swell band.

\paragraph{Near-bed velocity, stress and moments.} Each bin of the velocity FFT is scaled from
the sensor to the bed by $1/\cosh(kz_s)$ (linear theory, $u \propto \cosh kz$ with $z$ up from
the bed) and inverse transformed; $U_b$ is the rms of $\sqrt{u_\text{bed}^2+v_\text{bed}^2}$ and
$A_w$ the orbital excursion. Earlier revisions of this guide gave the factor as
$\cosh(kH)/\cosh[k(H-z_s)]$, which the code's own header records as the original, wrong form.
Wave bed shear stress uses the Swart (1974) friction factor with $T_p$, and roughness
$k_s = 2.5\,D_{84}$ where the site has a measured grain-size distribution
(\code{shared/site\_grain\_size.m}), otherwise the legacy $k_s = 10\,D_{50}$ with the
placeholder $D_{50} = 0.25$~mm. In catalog 2026-10-14.1, 19 of 65 records use a measured
distribution, 4 an assumed site default (217.4~$\mu$m) and 42 the placeholder. Reynolds
stresses and turbulent kinetic energy come from the detrended velocities. Velocity skewness and
asymmetry (Hilbert form, negative for the forward-pitched shoaling shape) are in the \code{vmom}
sub-struct.

\subsection{L3: wave forcing characterization}
\label{sec:l3methods}

\paragraph{Bands and storms.} $S_\eta$ is integrated over infragravity (0.004--0.04~Hz), swell
(0.04--0.10~Hz) and sea (0.10--0.25~Hz) bands, with a dominant-band flag by energy flux. Storms
are exceedances of $H_s > 1.5$~m lasting at least 6~h, merged across gaps under 12~h (fixed in
\code{PUV\_L3\_storms.m}). Hourly CDIP MOP output for a window 7~days beyond each end of the
record flags storms that fell in PUV data gaps.

\paragraph{Transport proxies.} Bottom energy flux $F_b = \rho g \int c_g S_\eta\,df$ over the
sea--swell band, and its running sum. Shields parameter
$\theta = \tau_b/[(\rho_s-\rho)gD_{50}]$ from the L2 wave stress, with the Soulsby--Whitehouse
critical value and a mobilization flag. Kinematic viscosity comes from each segment's mean
temperature (\code{shared/seawater\_nu.m}, with \code{Tvalid} screening the temperature), and
settling velocity from Ferguson and Church (2004) with nominal-diameter constants $C_1 = 20$,
$C_2 = 1.1$. The Rouse number uses the mean combined wave--current stress $\tau_m$ (Soulsby
1997; since 2026-08-13, before which the wave-stress amplitude overstated suspension), and is
also given at $D_{16}$, $D_{50}$ and $D_{84}$ where a measured distribution exists. Six
settling-velocity formulas could not be distinguished against the TBR23 surveys; they spread
about $\pm15$\% at 250~$\mu$m.

\paragraph{Tides and currents.} The tidal depth reference is the NOAA prediction for the
config's \code{cfg.tideStation} (\code{shared/noaa\_tide\_predictions.m}); every San Diego config
uses 9410230 (La Jolla, Scripps Pier). A config with no station gets 9410230 only when its
instruments lie in San Diego County; elsewhere L3 stops with an error. Catalina (CAT21A/B) also
uses 9410230, about 110~km away, as a flagged approximation: the nearest harmonic station,
9410079 Avalon, differs by 2.8~cm rms over the CAT21A record. The station used is stored at
\code{L3.tidal.station} and in the provenance, and the push refuses an L3 whose station no longer
matches its config. Tidal harmonic analysis (\code{t\_tide}, complex $u+iv$, seeded with
\code{rng(0,'twister')} so the bootstrap is reproducible) runs on the segment-mean velocities
over the span where velocity exists. Subtidal residuals (observed minus tidal) carry the
wave-driven mean flow, including undertow. A failed NOAA download or a missing \code{t\_tide} is
an error unless \code{opts.allowTtideFallback} or \code{opts.allowNoTides} is set.

\subsection{L4: nonlinear and infragravity diagnostics}

\code{PUV\_L4\_eta} band-passes pressure-derived surface elevation (total, swell, infragravity);
\code{PUV\_L4\_reflection} splits infragravity motion into incident and reflected parts
(Sheremet method); \code{PUV\_L4\_boundwave} separates bound from free infragravity with the
Hasselmann second-order kernel, and \code{PUV\_L4\_reflection\_free} repeats the split on the free
part, which gives the shoreline reflection that \code{L4.ref} alone overstates. The second-order
theory over-predicts the bound part above $H_s/h \approx 0.10$, so filter on $H_s/h$ before
using \code{bound\_frac}. \code{PUV\_L4\_bispectra} gives bicoherence, skewness and asymmetry
($K = 6$ sub-segments per hour, 60 degrees of freedom, 95\% bicoherence level 0.316);
\code{PUV\_L4\_moments} and \code{PUV\_L4\_velocity\_pdf} give frequency-resolved moment
correlations and pooled velocity histograms. Full field lists are in
\code{docs/pipeline\_levels.md}.

\section{Validation}
\label{sec:validation}

\begin{itemize}
\item \textbf{Against the MOP wave model.} PUV wave heights were compared with CDIP MOP spectra
  shoaled to the instrument depth. Analyses of April--July 2026 found the systematic difference
  organized by wave nonlinearity ($H_s/h$, Ursell number): the PUV has extra energy near the
  second harmonic of the peak that the linear model does not carry, with bound infragravity
  waves as its difference-frequency counterpart. A separate, real difference in directional
  spread does not explain the energy difference. An earlier conclusion that the model broadens
  the spectral peak was retracted in July 2026 as an artifact of comparing spectra on mismatched
  frequency grids. These results were computed on the catalog as it stood in July and are
  recorded, with the retractions, in \code{docs/compile\_sections.pdf}; current versions are
  maintained with the paper that uses them.
\item \textbf{Against an independent prior pipeline.} On Ruby2D MOP582\_6m (Torrey Pines,
  October 2021 to February 2022; 2,322 matched hours, April 2026, 17-minute segments on the new
  side) the new pipeline reproduced the legacy archived L2 with $R^2$ of 0.98 for $H_s$
  (5~cm rms), 0.93 for mean direction, 0.88 for directional spread and 0.76 for $T_p$. Each fault
  of the legacy code measured in isolation, and which legacy products are safe to reuse, is in
  \code{docs/legacy\_pipeline\_defects.pdf}: $H_s$ and mean direction are usable, directional
  spread and $b_2$ (hence radiation stress) are not.
\item \textbf{Mean cross-shore flow.} In May 2026 the segment-mean cross-shore velocity of 38
  instruments was tested against real Stokes return flow, a constant calibration offset and
  random Doppler noise, and matched return flow in sign, magnitude and response to averaging
  length. That run predates the heading corrections of 2026-05-14 (one included record had its
  velocity sign reversed) and later rebuilds, and has not been repeated.
\item \textbf{Binary decoder.} Besides the bit-exact match to ASCII (\S\ref{sec:vec}), the
  binary-decoded deployments' hourly $H_s$ was compared with CDIP MOP in July 2026: $R^2$ of
  0.88--0.94 with 1--4~cm bias for the modern 2~Hz records (TOR19W, TOR20W, IB19W), and
  0.5--0.9 for the firmware-1.21 records, which sit farther from their MOP transects
  (\code{docs/recopied\_data\_backlog.md}). Mean vertical velocity near zero in every decoded
  record supports the decode and the rotation.
\item \textbf{Tests.} \code{run\_all\_tests} runs 23 self-contained tests, including synthetic
  closure tests of the pressure correction, the Z-test, channel QC, provenance, the tide station,
  the gap fill and the known-failure handling.
\end{itemize}

\section{Known limitations}
\label{sec:limits}

\begin{itemize}
\item \textbf{Disputed headings.} 12 records keep a compass heading more than 10\degree\ from the
  logged mount heading (\code{shared/heading\_disputed\_records.m}); their directional quantities
  are uncertain by at least that much.
\item \textbf{Grain size.} 42 of 65 records use the placeholder $D_{50}$; bed stress, Shields,
  mobilization, settling velocity and Rouse on those records will move when measured values
  arrive. L4 does not depend on $D_{50}$.
\item \textbf{Fixed \code{doffp}.} The bed can move tens of centimeters during a deployment (logged
  changes up to 23~cm). That moves depth and depth-normalized quantities ($H_s/h$, Ursell) by
  about 3\% and bed stress by under 0.3\%. A PUV cannot measure its own \code{doffp}. IB18W and
  IB19S carry values whose source is unknown.
\item \textbf{Off-bed pressure QC is off} until the next deliberate L1 rebuild; no L2 segment in
  the catalog is affected.
\item \textbf{Catalina tidal depth} is La Jolla's (\S\ref{sec:l3methods}).
\item \textbf{Unsourced geometry.} 69 \code{doffp}/\code{latlon}/\code{shorenormal} values had no
  on-line source at the last audit (2026-07-28); treat them as unverified.
\end{itemize}

\section{Troubleshooting and where to look next}
\label{sec:troubleshooting}

\begin{itemize}
\item \textbf{A driver ends with an error.} Read the list it prints: configs that threw and
  records not written. Known field failures are skipped and do not cause it.
\item \textbf{A config change seems to have no effect, or a deployment vanished from a batch.}
  Run \code{validation/audit\_registry\_loads.m}; batch loops skip a config that throws.
\item \textbf{L3 stops on tides.} Check \code{t\_tide} is on the path, \code{cfg.tideStation} is
  set, and NOAA is reachable.
\item \textbf{Network reads are slow.} Cache raw files with \code{copy\_raw\_to\_local(cfg)}.
\item \textbf{Little velocity survives a storm.} Check the failure signature
  (\S\ref{sec:signatures}): a sensor-block failure is recoverable, a topple is not. Confirm
  \code{Tvalid} is set to the site range.
\item \textbf{Recovered (\qcflag{3}) data in an analysis.} Filter to \qcflag{1} for clean-only,
  or include \qcflag{3} knowing the scale uncertainty.
\end{itemize}
